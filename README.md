# PulseRx: HCP Targeting, Call Planning & Territory Sizing

A commercial pharma analytics exercise on **synthetic data**: decile prescribers, set a call plan,
check whether the field force can deliver it, and find where today's calls are going instead.

Built to practise the tool chain commercial analytics teams use -- **SQL, an Alteryx-style ETL
workflow, and Tableau** -- on a problem with a real answer. The companion project
[PharmaTarget](https://github.com/rajmodi262/pharmatarget) does the same kind of work on 29 GB of
real CMS Medicare data; this one trades real data for a full, runnable tool chain.

## What is real here, and what isn't

| Piece | Status |
|---|---|
| Data (`data/`) | **Synthetic.** Brands, prescribers, reps and calls are invented by `data/generate_data.py`. |
| Python pipeline (`alteryx/run_pipeline.py`) | Runs; produces every mart in `output_marts/`. |
| SQL (`sql/`) | Runs on DuckDB against the CSVs; tests check it matches the pipeline row for row. |
| Alteryx workflow (`alteryx/*.yxmd`) | Hand-authored for Designer 2023.2, well-formed, same rules as the pipeline (tested). **Not yet opened or run in Alteryx Designer.** Checklist in `alteryx/ALTERYX_WORKFLOW_GUIDE.md`. |
| Tableau workbook (`tableau/*.twb`) | Starter file: data source, 4 calculated fields (incl. a FIXED LOD), 2 worksheets. **No dashboard yet.** Build spec in `tableau/TABLEAU_DASHBOARD_GUIDE.md`. |
| Web dashboard (`web_dashboard/`) | Runs; every number and the what-if simulator are computed from the marts. |

## The business question

A brand with 31 reps across 14 territories asks: *are we calling on the right prescribers, and do
we need more reps to do it properly?*

1. **Who matters** -- decile every prescriber on 12 months of market TRx (decile 10 = top 10%).
2. **How often** -- a four-tier call plan: deciles 8-10 split by brand share at 22% into
   *protect* (18 calls/yr) and *convert* (14); deciles 5-7 get 6; deciles 1-4 get 1 and move to
   digital.
3. **Can we deliver it** -- compare the plan's calls with rep capacity (720 calls per rep per year),
   territory by territory.
4. **Where do calls go today** -- compare the CRM call log with the plan.

**Reading it:** the field force is big enough -- the plan fits inside current capacity -- but
today's calls follow access rather than value, so a large share of high-value prescribers are never
seen while low-value ones are over-called. That is a *retarget, don't hire* answer, and every part
of it except the dollar scenario is arithmetic on the data.

### How the misallocation got there (it is planted)

The synthetic reps build call lists mostly on *access* -- community clinics, in-person-only doctors,
habit -- controlled by one parameter, `CALL_TARGETING_ALIGNMENT` in `data/generate_data.py`
(0 = pure access, 1 = pure volume; default 0.25). The pipeline never reads that parameter. The test
`test_pipeline_detects_planted_misallocation` regenerates the data at 0 and 1 and checks the
pipeline finds many uncalled high-value prescribers in the first case and almost none in the second.

## Run it

```bash
pip install -r requirements.txt
python data/generate_data.py            # synthetic raw files -> data/
python alteryx/run_pipeline.py          # marts -> output_marts/
python analysis/headline_metrics.py     # metrics JSON + the Results table above
python tableau/sync_twb_columns.py      # keep the .twb column list in step with the mart
python web_dashboard/prep_dashboard_data.py
python -m http.server 8085 --directory web_dashboard   # open http://localhost:8085
python -m pytest -q
```


## Limits

- Synthetic data: the result shows the method works, not what any real brand should do.
- Deciles are on volume only. PharmaTarget shows why volume alone misses opportunity (a high-volume
  prescriber at 90% share has little left to win); the share split in the tiers is a first step
  toward that, not the full model.
- No call-response signal exists in this data, so the dollar figure is a scenario with a stated
  assumption and range.
